핵심 콘셉트
“공동 집필자”이자 “편집자”인 작가를 불러 집필 회의를 하고, 필요한 내용만 “메모”로 남긴다.

RP를 진행하다 보면 캐릭터와 대화하는 것과 별개로 이런 이야기를 하고 싶을 때가 있음.

  • 다음 장면을 어떻게 전개할지
  • 인물의 행동에 개연성이 있는지
  • 지금까지 깔아둔 복선을 어떻게 회수할지
  • 특정 캐릭터의 감정선이 자연스러운지
  • 작가가 현재 설정을 어떻게 이해하고 있는지
  • 다음 사용자 인풋에서 무엇을 유도할지

이런 이야기를 본편에서 직접 꺼내면 몰입이 깨지고 집필 상담 내용이 본편 컨텍스트에 섞임. 그래서 본편과 분리된 집필 회의실을 만들었음.

집필 회의

[사진 삽입 · 집필 회의 탭]

집필 회의에서는 현재 RP를 알고 있는 “작가”와 자유롭게 대화할 수 있음.

작가는 사용자를 이야기 속 등장인물이 아니라 공동 집필자이자 편집자로 인식함. 다음 장면, 인물의 동기, 복선, 전개 속도, 설정 충돌 등을 본편 밖에서 함께 검토할 수 있음.

중요: 집필 회의에서 나눈 대화는 그 자체로는 본편에 아무런 영향을 주지 않음.

작가는 사용자가 메모의 생성·수정·삭제를 명시적으로 요청했을 때만 메모 작업을 제안하도록 설계되어 있음. 제안이 나와도 자동으로 반영되지 않고 사용자가 직접 선택함.

  • 메모에 적용: 실제 메모에 반영
  • 무시: 제안을 거절
  • 아무것도 누르지 않음: 대기 상태로 유지

대기하거나 무시한 메모 제안도 집필 회의의 대화 기록에는 상태와 함께 남음. 작가는 이전에 무엇을 제안했고 사용자가 그것을 보류하거나 거절했는지 기억하지만, 활성 메모로 취급하지는 않음.

회의실을 여러 개 만들어 전환할 수 있으며, 새 회의실의 기본 이름은 (현재 봇 이름) 회의실 (번호) 형식임.

각 메시지는 개별적으로 수정하거나 삭제할 수 있음. 사용자 메시지는 내용만 고치거나, 해당 시점부터 이후 회의를 지우고 다시 보낼 수도 있음.

메모

[사진 삽입 · 메모 탭]

집필 회의에서 새 메모 생성안을 적용하면 (현재 봇 이름) 메모 폴더 안에 자동으로 들어감. 해당 폴더가 없으면 새로 만들어짐.

폴더와 메모는 자유롭게 생성·수정·삭제하고 각각 ON/OFF 할 수 있음. 제목을 눌러 접거나 펼칠 수도 있고, 펼친 메모는 넓은 편집창에서 바로 수정할 수 있음.

폴더 이름에는 봇 이름이 들어가지만 회의실과 메모 자체는 특정 봇에 종속되지 않는 전역 자료임. 다른 봇으로 이동해도 그대로 사용할 수 있고, 봇을 삭제해도 함께 사라지지 않음.

메모가 본편에 적용되는 방식

[사진 삽입 · 사용자 인풋 아래의 작가 메모 표시]

폴더와 개별 메모가 모두 ON인 메모만 활성 메모가 됨. 본편에서 채팅을 보내면 활성 메모가 모델 요청의 마지막 사용자 인풋 뒤에 다음과 같은 형식으로 붙어서 전달됨.

사용자 인풋:
A는 깜짝 놀라 뒤돌아본다.

(Memo(1): A의 뒤에 나타난 것은 B였다.)

이 내용은 모델에게 보내는 요청에서만 추가됨. RisuAI에 저장된 실제 사용자 메시지 자체를 수정하지는 않음. 사용자가 확인할 수 있도록 본편 화면에는 이번 요청에 어떤 메모가 포함됐는지 별도로 표시됨.

화면과 요청에 표시되는 Memo 번호는 현재 활성화된 메모만 기준으로 다시 매겨지므로 번호가 끝없이 쌓이지 않음.

활성 메모에 로어북 활성화 키가 들어 있으면 해당 키도 본편 로어북 검색에 사용됨. 위 예시에서는 사용자 인풋에 B가 없어도 메모에 B가 있으므로, 지원 범위 안에서 B를 활성화 키로 가진 로어북이 같은 요청에 포함될 수 있음.

컨텍스트

[사진 삽입 · 컨텍스트 탭 전체]

컨텍스트 탭에서는 작가에게 전달할 참고 자료를 직접 관리할 수 있음.

  • 캐릭터 디스크립션: 캐릭터 이름과 디스크립션
  • 페르소나: 페르소나 이름과 디스크립션
  • 퍼스트 메시지: 기본 퍼메와 추가 퍼메 중 하나를 선택
  • 이전 본편 대화
  • 작가의 노트
  • 글로벌 노트 덮어쓰기
  • 캐릭터·챗·모듈 로어북
  • 하이파/수파 메모리 장기 기억
  • 기타

각 항목은 개별적으로 ON/OFF 할 수 있고, 작가에게 실제로 전달될 것으로 예상되는 토큰 수도 확인할 수 있음.

맨 아래의 기타는 기본적으로 OFF임. 성격, 시나리오, 예시 대화, 캐릭터 시스템 프롬프트, 포스트 히스토리 지시문, 각종 추가 노트, 제작자 정보, 캐릭터 버전, 태그처럼 일반적인 채팅에서 거의 사용하지 않거나 메타데이터에 가까운 항목이 모여 있음.

작가용 로어북

[사진 삽입 · 로어북 ON / AUTO / OFF와 현재 활성 상태]

각 로어북은 작가에게 전달할 상태를 따로 선택할 수 있음.

ON · 항상 전달 AUTO · 본편 상태를 바탕으로 판정 OFF · 전달하지 않음

이 설정은 작가에게 제공되는 컨텍스트에만 적용됨. 본편 로어북의 실제 상태나 RisuAI 설정은 변경하지 않음.

AUTO는 본편의 검색 깊이, 활성화 키, 보조 키, 재귀 검색 설정 등을 가능한 범위에서 재현해 판정함. 지금 활성화됐는지와 그 이유도 화면에서 확인할 수 있으며, 로어북 폴더 전체 또는 내부 항목별로 상태를 바꿀 수 있음.

CBS 문법 처리

[사진 삽입 · 녹색 / 적색 / 갈색으로 표시된 CBS 처리 결과]

캐릭터 디스크립션이나 로어북에서 사용하는 CBS 문법도 가능한 범위에서 RisuAI의 동작을 재현하도록 만들었음.

  • 녹색: 현재 조건에서 적용되는 문법과 내용
  • 적색: 현재 조건에서 제외되는 내용
  • 갈색: 플러그인이 해석하지 못한 문법

미지원 문법은 항목별로 원문 그대로 작가에게 전달할지, 컨텍스트에서 제외할지 선택할 수 있음.

확률 판정 등 일부 RisuAI 기능은 지원하지 않음. 이런 경우에는 미지원 기능 안내를 표시하고, 잘못 판정한 내용을 작가에게 전달하지 않도록 처리함.

토큰 확인

[사진 삽입 · 토큰 확인 패널]

집필 회의의 토큰 확인 버튼에서는 다음 정보를 확인할 수 있음.

  • 다음 작가 요청의 입력 토큰 추정치
  • 최근 작가 답변의 토큰 추정치
  • 최대 출력 토큰
  • 현재 RisuAI의 최대 컨텍스트 크기
최대 컨텍스트를 초과할 것으로 예상됩니다.
요청이 실패하거나 일부 대화 및 컨텍스트가 처리되지 않을 수 있습니다. 과거 대화 또는 불필요한 컨텍스트를 정리해 주세요.

토큰 수는 정확한 모델 토크나이저 결과가 아니라 플러그인의 추정치이므로 참고용임.

설정

[사진 삽입 · 설정 탭]

작가 모델은 Main model과 Sub model 중에서 선택할 수 있음. 집필 회의는 본편과 별도의 모델 요청이므로 선택한 모델 공급자의 사용량이나 비용이 발생할 수 있음.

집필 회의 마크다운 정리

작가 답변에서 과도하게 사용되는 볼드·이탤릭·헤더 형식과 후행 공백을 기계적으로 정리하는 옵션임. 화면에서만 숨기는 것이 아니라 실제 집필 회의 기록을 정리하므로 이후 대화의 토큰 절약에도 영향을 줌.

시스템 프롬프트

작가의 핵심 동작을 정하는 기본 시스템 프롬프트와 장르·말투·분석 성향을 정하는 추가 시스템 프롬프트로 나뉨.

각 계층의 내장 프리셋은 수정하거나 삭제할 수 없지만, 복제해서 자유롭게 고칠 수 있음. 사용자 프리셋은 원하는 만큼 추가·수정·삭제하고 전환할 수 있음.

권한 안내

[사진 삽입 · RisuAI 권한 확인 창]

처음 임포트하면 컨텍스트 확인, 본편 화면의 메모 표시, 활성 메모 주입에 필요한 RisuAI 권한 확인 창이 나타남.

권한을 허용하지 않아도 가능한 범위에서는 작동하지만 관련 기능이 제한될 수 있음. 임포트 직후 권한 확인이 나타나지 않으면 RisuAI를 한 번 새로고침해 주면 됨.

플러그인은 API 키를 직접 입력받거나 저장하지 않음.
