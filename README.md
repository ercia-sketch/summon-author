# ★작가 소환★ / ★Summon Author★ v1.1.0 (`author_talk`)

RisuAI의 현재 RP를 참고하면서 별도의 집필 회의를 진행하는 API 3.0 플러그인입니다.

## v1.1.0 업데이트

- 컨텍스트의 **이전 대화**를 사용자·캐릭터 메시지별 카드로 나누고, 실제 페르소나와 캐릭터 이름을 표시합니다. 이름을 눌러 본문을 접거나 펼칠 수 있고, 각 메시지를 개별적으로 작가 컨텍스트에서 제외할 수 있습니다.
- 이전 대화를 전체 또는 개별적으로 꺼도 작가용 로어북 AUTO 판정은 본편 대화 전체를 계속 검색합니다. 이 선택은 작가에게 보내는 이전 대화에만 영향을 주며 RisuAI의 채팅 기록과 로어북 상태를 바꾸지 않습니다.
- 설정에 접을 수 있는 **정규식 스크립트** 관리자를 추가했습니다. 이름, `IN`, `OUT`을 입력하면 저장 버튼 없이 반영되며, 모든 규칙은 `g` 플래그로 위에서 아래 순서대로 작가 컨텍스트에 적용됩니다. 드래그로 순서를 바꿀 수 있고 잘못된 정규식은 건너뛰며 오류를 표시합니다.
- `OUT`이 비어 있는 규칙은 일치한 내용을 작가 컨텍스트에서 제거합니다. 대체·제거된 위치는 보라색으로 표시되며 눌러서 해당 규칙 적용 직전 텍스트와 결과를 전환해 확인할 수 있습니다.
- 컨텍스트의 모든 토큰 배지를 **현재 작가에게 전달되는 토큰/원문 전체 토큰** 형식으로 통일했습니다. OFF, CBS 처리, 미지원 문법 제외, 개별 대화 선택, 로어북 활성 상태와 정규식 처리 결과가 분자에 반영됩니다.

## v1.0.5 패치

- 본편 채팅의 시각적 작가 메모 표시를 하나의 직렬화된 작업으로 관리하여, 최초 표시·재시도·복구 감시가 겹쳐도 같은 메모가 중복 표시되지 않게 했습니다.
- 서로 다른 활성 메모는 합치지 않고 각각 별도의 안내 상자로 표시하며, 기존 실제 요청 주입 형식은 변경하지 않았습니다.
- 개별 메모의 삭제 버튼을 펼친 편집 영역의 저장 버튼 옆에서 메모 상단 ON/OFF 토글 옆으로 옮겼습니다.

## v1.0.4 패치

- Main/Sub 모델이 다른 플러그인에서 제공되는 모델이어도 집필 회의에서 호출할 수 있도록 허용했습니다.

## v1.0.3 패치

- 대기 중이거나 사용자가 무시한 메모 제안을 다음 작가 요청의 일반 대화 기록에 상태와 함께 포함합니다. 작가는 제안 내용을 기억하되, 대기·무시된 제안을 활성 메모로 취급하지 않습니다.

## v1.0.2 패치

- 집필 회의와 각 관리 탭의 세로 스크롤바를 패널 오른쪽 가장자리에서 10px 안쪽으로 옮겨, 크기 조절 영역과 겹치지 않도록 했습니다.

## v1.0.1 패치

- 집필 회의의 빈 화면 안내를 실제 동작과 일치하도록 **활성화된 작가 컨텍스트와 활성 메모를 참고한다**는 표현으로 수정했습니다.

## v1.0.0 정식 릴리즈

- 플러그인의 한국어 표시명을 **★작가 소환★**, 영문명을 **★Summon Author★**로 확정했습니다.
- 내장 기본 시스템 프롬프트가 세부 자료명을 중복 열거하지 않고, 활성화된 **Writer Context** 항목과 활성 메모만 사용하도록 간결하게 정리했습니다.
- 사용되지 않는 이전 컨텍스트 렌더러, CBS 보조 렌더러, 메모 확인 함수와 관련 CSS를 제거했습니다.
- 내부 식별자와 `author_talk:` 저장소 키는 기존 회의실·메모·설정의 호환성을 위해 유지합니다.

- 저장 데이터를 읽지 못한 경우 기본값으로 덮어쓰지 않고 해당 저장 키를 보호합니다. 설정 읽기 오류가 있으면 기본 설정으로 화면을 열되, 오류가 해결되기 전까지 설정 저장을 차단합니다.
- 작가 메모 작업의 실행 취소는 전체 메모 목록을 복원하지 않고 해당 작업이 바꾼 메모만 되돌립니다. 적용 후 같은 메모가 직접 수정되었다면 다른 변경을 지우지 않도록 실행 취소를 거부합니다.
- v0.15.5 이전에 전체 스냅샷으로 저장된 메모 작업에는 안전하지 않은 실행 취소 버튼을 제공하지 않습니다.
- 메모로 새롭게 활성화된 본편 로어북은 대화와 메모를 같은 활성화 규칙으로 비교하고, 현재 CBS 처리 결과를 사용합니다. 본편의 로어북 재귀 검색 설정도 따르며 이미 포함된 항목은 중복 주입하지 않습니다.
- 플러그인이 지원하는 `and`, `or`, `not`, `tonumber` CBS 결과를 RisuAI의 동작과 일치시켰습니다.
- 작가 모델이 여러 후보를 반환하면 첫 번째 작가 답변만 사용하고 나머지는 표시하거나 저장하지 않습니다. 누적형 스트림과 분할 UTF-8 응답도 안전하게 합칩니다.
- 작가 응답 중 봇 또는 채팅 전환을 감지하면 이전 요청을 중단합니다. 취소할 수 없는 응답은 무시하고 전송 버튼을 다시 활성화합니다.
- 플로팅 패널을 열지 않았어도 메모 주입 시점에 본편의 시각적 메모 표시를 독립적으로 준비합니다.
- 플러그인 종료 시 저장 오류와 관계없이 요청·메모 훅·감시자·리사이즈 요소를 각각 정리합니다.

## 현재 인터페이스

- 플로팅 패널 전체를 어두운 반투명 계열의 단일 디자인 시스템으로 개편했습니다.
- 헤더에는 현재 버전과 활성 메모 수, 세션 이름을 함께 표시하며 새로고침·최소화·닫기 동작을 코드 내 SVG 아이콘으로 구분합니다.
- 현재 선택한 탭에만 파란 밑줄을 표시하고 집필 회의, 메모, 컨텍스트, 설정 화면의 카드·버튼·입력창·상태 배너를 같은 규칙으로 통일했습니다.
- 컨텍스트 통계는 아이콘 없이 간결한 텍스트 칩으로 표시하고, 각 참고 자료는 제목·토큰·경고·탐색·토글을 한 행에서 확인할 수 있습니다.
- 좁은 패널에서는 헤더 버튼의 문구를 생략하고 아이콘만 남기며, 키보드 포커스와 스크롤바도 새 디자인에 맞춰 표시합니다.
- 크기 조절용 8방향 판정 영역은 그대로 유지하되 테두리와 핸들은 화면에 표시하지 않습니다.
- 복원·최소화 상태의 헤더 구성 요소 크기를 통일하고 최소화 헤더를 수직 중앙에 배치했습니다.
- 상태 및 컨텍스트 안내 상자의 여백과 글자 크기를 줄이고, 메모 탭의 내부 훅 준비 표시는 제거했습니다.
- 최소화 상태에서도 현재 봇·채팅 이름과 새로고침 버튼을 유지하며, 최소화 상태의 새로고침은 패널을 먼저 복원합니다.
- 탭 막대의 높이를 줄이고 집필 회의의 사용자 메시지 표기를 **사용자**로 통일했습니다.
- 메시지를 수정하거나 하나만 삭제할 때 집필 회의의 기존 스크롤 위치를 유지합니다.
- 각 컨텍스트 항목의 가장 오른쪽에서 미지원 문법을 작가에게 전달할지 독립적으로 선택할 수 있으며, 기본값은 전달하지 않음입니다.
- 미지원 문법 전달 설정을 `전달 안 함/전달함` 두 버튼으로 개편하고, 개별 항목의 선택값에만 파란 테두리를 표시합니다.
- 컨텍스트 순서를 캐릭터·페르소나·퍼스트 메시지·이전 대화·노트·로어북·장기 기억 순으로 정리하고, `기타`는 구분선 아래의 회색 카드로 분리했습니다.
- 좁은 패널에서 제목이 한 글자씩 세로로 찌그러지지 않도록 컨텍스트와 로어북 헤더를 반응형 그리드로 변경했습니다.
- 컨텍스트 상단의 성공 알림과 본편 비영향 안내 상자는 작은 쪽을 기준으로 크기를 통일하고 간격을 줄였습니다.
- 컨텍스트 ON/OFF 토글의 흰색 원을 절대 위치와 중앙 정렬 방식으로 보정해 양쪽 및 위아래 여백을 균일하게 만들었습니다.
- 시스템 프롬프트 제목과 프리셋 관리 버튼을 같은 행에 정렬하고 아래 선택창과의 간격을 확보했습니다.
- 컨텍스트, 마크다운 표시, 메모 폴더와 개별 메모의 모든 슬라이드 토글이 같은 크기·색상·원 위치·전환 속도를 공유하도록 통일했습니다.
- 메모 폴더가 OFF일 때 중복 설명인 `내부 메모 모두 미포함` 문구를 제거했습니다.

## 설치

1. RisuAI의 **설정 → 플러그인** 화면을 엽니다.
2. 플러그인 가져오기에서 [`summon_author_v1.1.0.js`](./summon_author_v1.1.0.js)를 선택합니다.
3. 플러그인을 활성화합니다.
4. 채팅창 우측 메뉴에서 **★작가 소환★**을 누릅니다.

`summon_author_v1.1.0.js`는 외부 파일이나 라이브러리가 필요 없는 단일 설치 파일입니다. 이후 배포 파일도 파일명에 버전을 표시합니다. `src` 폴더와 빌드 설정은 개발 및 유지보수용이므로 RisuAI에 함께 넣을 필요가 없습니다.

## 동작 범위

- 집필 회의 기록, 메모, 작가용 로어북 상태와 프롬프트 프리셋은 플러그인 전용 저장소에 보관됩니다.
- 회의실과 메모는 특정 봇에 종속되지 않는 전역 자료입니다. 어떤 봇을 열어도 같은 회의실과 메모 폴더를 자유롭게 선택·활성화·비활성화·삭제할 수 있습니다.
- 봇을 삭제해도 전역 회의실과 메모는 삭제되지 않습니다. 반면 작가용 로어북 ON/OFF/AUTO 선택은 로어북 구성이 다른 봇 사이에서 섞이지 않도록 계속 봇별로 저장됩니다.
- 여러 회의실을 만들 수 있으며, 각 회의실의 집필 회의 기록은 서로 독립적입니다. 회의실을 사용할 때 작가가 참고하는 봇 카드와 본편 컨텍스트는 현재 열려 있는 봇을 기준으로 새로 구성됩니다.
- 새 회의실의 기본 이름은 **(현재 봇 이름) 회의실 (번호)** 형식이며, 같은 봇 이름으로 만든 기존 회의실에서 비어 있는 가장 작은 번호를 제안합니다. 이름은 생성 전에 자유롭게 바꿀 수 있습니다.
- 기존 버전의 봇별 회의실과 메모는 최초 실행 시 전역 자료로 한 번 병합됩니다. 원본 봇별 저장 데이터는 안전을 위해 자동 삭제하지 않습니다.
- 사용자와 작가의 각 메시지는 따로 삭제하거나 단순 수정할 수 있습니다. 사용자 메시지는 수정한 시점부터 이후 회의 기록을 지우고 새 분기로 다시 보낼 수도 있습니다. 이미 명시적으로 적용한 메모는 자동으로 되돌리지 않습니다.
- 메모는 폴더로 관리할 수 있습니다. 폴더와 개별 메모가 모두 ON일 때만 활성 메모가 됩니다.
- 폴더와 개별 메모의 제목을 눌러 각각 접거나 펼칠 수 있으며, 접힘 상태는 다시 열어도 유지됩니다. 펼친 메모는 작가 컨텍스트의 상세 자료와 비슷한 형태로 표시되고, 플로팅 패널의 세로 공간을 넉넉히 사용하는 편집창에서 바로 수정할 수 있습니다.
- 플로팅 패널 최상단에는 현재 활성 메모 개수가 항상 표시되며, 패널을 최소화해도 확인할 수 있습니다.
- 화면과 모델에 보이는 `Memo(n)` 번호는 현재 활성 메모만 오래된 순서대로 다시 매깁니다. 저장에는 계속 증가하는 숫자 대신 내부 UUID를 사용하므로, 메모를 지웠다가 만들어도 표시 번호가 불필요하게 누적되지 않습니다.
- 활성 메모 때문에 새롭게 활성화된 본편 로어북은 같은 모델 요청에 보충됩니다. 대화만으로 활성화된 결과와 대화·메모를 함께 검색한 결과를 비교하고, 이미 RisuAI가 포함한 로어북은 중복을 피합니다. 로어북 재귀 검색은 현재 본편 설정이 켜진 경우에만 같은 방식으로 적용합니다.
- 집필 회의는 캐릭터 이름과 디스크립션, 선택된 페르소나 설명, 저장된 Hypa/SupaMemory 장기 기억, 유효한 본편 대화 전체, 선택한 퍼스트 메시지, 작가의 노트, 글로벌 노트 덮어쓰기, 작가용으로 활성화된 로어북과 활성 메모를 참고합니다. 성격·시나리오·예시 대화·카드 제작자 정보 등은 컨텍스트 맨 아래의 **기타**에 모이며 기본값은 OFF입니다.
- 작가 응답은 별도 모델 요청입니다. 선택한 모델 공급자의 사용량 또는 비용이 발생할 수 있습니다.
- 작가가 출력한 메모 작업은 먼저 미리보기로 표시되며, 사용자가 **메모에 적용**을 눌러야 반영됩니다.
- 작가가 제안한 새 메모를 적용하면 **(현재 봇 이름) 메모** 폴더에 생성됩니다. 해당 이름의 폴더가 없을 때만 자동으로 만들며, 기존 폴더가 OFF라면 그 상태를 임의로 바꾸지 않습니다.
- 진행 중인 작가 요청이 멈춘 경우 상단 **요청 취소·새로고침**을 누르면 즉시 새 요청을 보낼 수 있습니다. 취소할 수 없는 이전 응답은 도착하더라도 화면이나 기록에 반영하지 않습니다.
- 작가 화면은 RisuAI 위의 이동·크기 조절·최소화 가능한 플로팅 패널로 열립니다. 네 꼭짓점과 상·하·좌·우 변의 총 8개 핸들로 크기를 조절할 수 있습니다. 드래그 중에는 투명한 실드가 포인터를 이어받아 빠르게 움직여도 iframe 경계에서 조작이 끊기지 않도록 합니다. 패널 밖의 RisuAI 기능도 계속 사용할 수 있습니다.
- 컨텍스트의 참고 자료 크기는 글자 수가 아니라 언어 구성을 고려한 **근사 토큰 수**로 표시합니다. 모든 배지는 **현재 작가에게 전달되는 토큰/원문 전체 토큰** 순서입니다. 전체뿐 아니라 캐릭터 디스크립션, 기타, 페르소나, Hypa/SupaMemory 장기 기억, 이전 본편 대화와 개별 메시지, 퍼스트 메시지, 각 노트와 로어북의 예상치도 확인할 수 있습니다. ON/OFF, CBS 판정, 미지원 문법 제외, 정규식 대체·삭제 결과가 분자에 반영되며 실제 모델 토크나이저와는 차이가 날 수 있습니다.
- 집필 회의 입력창의 **토큰 확인**은 다음 요청의 입력 토큰 추정치, 다음 요청의 최대 출력 토큰, 최근 작가 답변의 토큰 추정치와 RisuAI의 최대 컨텍스트 크기를 표시합니다. 가로 그래프의 파란색은 다음 입력, 초록색은 다음 최대 출력을 뜻하며 회색은 남은 컨텍스트입니다. 최근 답변은 다음 입력 기록에 이미 포함되므로 그래프에 중복해서 더하지 않습니다. 입력 추정치와 최대 출력의 합이 최대 컨텍스트 이상이면 버튼이 붉게 바뀌고 요청 실패 또는 일부 컨텍스트 미처리 가능성을 경고합니다. 플러그인이 회의 기록을 자동으로 삭제하거나 축소하지는 않습니다.

## 마크다운 표시

집필 회의 상단의 **마크다운 표시**를 켜면 사용자·작가 메시지에 제목, 강조, 취소선, 인라인 코드, 코드 블록, 인용문, 목록과 안전한 링크를 표시합니다. 기본값은 OFF이며, 이 토글은 표시 방식에만 영향을 줍니다. 저장되는 회의 원문과 작가 모델에 보내는 내용은 바뀌지 않습니다.

모델 출력은 신뢰할 수 없는 텍스트로 취급합니다. 원시 HTML은 실행하지 않고 이스케이프하며, 링크는 `http`, `https`, `mailto` 또는 문서 내부 `#` 주소만 클릭 가능하게 만듭니다.

설정의 **집필 회의 마크다운 정리**는 별개의 기능입니다. 이 기능을 켜면 새로 보내거나 수정하는 사용자 메시지와 새 작가 응답을 저장하기 전에 다음 내용을 실제 텍스트에서 정리합니다.

- `**볼드**`, `*이탤릭*`, `***볼드 이탤릭***`의 강조 기호 제거
- 줄 끝의 불필요한 공백 제거(줄바꿈용 공백은 최대 두 칸 유지)
- `#제목`을 `# 제목`으로 정리
- 헤더 앞의 `1.` 또는 `I.` 번호와 헤더 끝의 `:` 제거

일반 별표 표현과 산술식, 인라인 코드 및 코드 블록 내부는 정리 대상에서 제외합니다. 기존에 저장된 회의 기록은 소급하여 변경하지 않습니다.

## 정규식 스크립트

설정의 **정규식 스크립트**에서 작가에게 보내는 컨텍스트를 플러그인 내부에서만 대체하거나 제거할 수 있습니다.

- `IN`에는 찾을 JavaScript 정규식을, `OUT`에는 바꿀 텍스트를 입력합니다. 모든 규칙은 `g` 플래그로 전체 검색하며 별도의 Custom Flag는 사용하지 않습니다.
- `OUT`을 비우면 일치한 텍스트를 제거합니다. `$1`, `$&`, `$<name>` 등 JavaScript 표준 치환 표기를 사용할 수 있습니다.
- 규칙은 화면의 위에서 아래 순서로 연속 적용됩니다. 아래 규칙이 받는 원문은 바로 위 규칙까지 처리된 결과이며, 드래그로 순서를 변경할 수 있습니다.
- 빈 `IN`은 아무 작업도 하지 않고, 문법이 잘못된 정규식은 컨텍스트 처리를 막지 않은 채 해당 규칙만 건너뜁니다.
- 적용 범위는 컨텍스트 탭의 각 참고 자료 본문입니다. 시스템 프롬프트, 집필 회의 기록, 활성 메모, 플러그인이 붙이는 구분 헤더와 대화 화자 이름, 로어북 활성화 키 및 판정 설정에는 적용되지 않습니다.
- 규칙과 순서는 플러그인 전역 설정으로 저장됩니다. 실제 캐릭터 카드, 페르소나, 본편 채팅, 노트, 로어북 원문은 수정하지 않습니다.

컨텍스트 화면에서 대체 결과와 삭제 표식은 보라색으로 표시됩니다. 이를 누르면 해당 규칙을 적용하기 직전의 일치 텍스트를 확인할 수 있습니다. 삭제 표식인 `[정규식에 의해 컨텍스트에서 제외]`는 화면 확인용이며 작가 요청이나 토큰 분자에는 포함되지 않습니다.

## CBS 조건부 참고 자료

작가용 참고 자료를 구성할 때 현재 채팅의 `scriptstate`와 캐릭터 기본 변수를 읽어, 다음과 같은 읽기 전용 CBS 문법을 처리합니다.

- `{{getvar::변수명}}`, `{{char}}`, `{{user}}`
- `{{#if ...}}`, `{{#if_pure ...}}`, `{{#when ...}}`, `{{:else}}`, `{{/}}`와 중첩 조건문
- `not`, `and`, `or`, `is`, `isnot`, `var`, `vis`, `visnot`, `>`, `<`, `>=`, `<=`
- 비교 함수와 `trim`, `length`, `lower`, `upper`, `capitalize`, 숫자 반올림 등 부작용이 없는 문자열·숫자 함수

처리는 캐릭터 디스크립션, 기타, 페르소나, Hypa/SupaMemory 장기 기억, 이전 본편 대화, 퍼스트 메시지, 작가의 노트, 글로벌 노트 덮어쓰기와 각 로어북 내용에 적용됩니다. 작가 요청을 보낼 때마다 현재 변수 상태로 컨텍스트를 다시 만들며, 전달 텍스트·화면 표시·경고·토큰 계산은 하나로 묶인 CBS 평가 결과를 사용합니다.

컨텍스트 화면에서는 활성 조건과 선택된 분기를 초록색, 비활성 분기를 접을 수 있는 빨간색 영역, 미지원 문법을 갈색으로 표시합니다. 이 색상 표시는 모델에 전달되는 CBS 판정 결과와 같은 조건 평가를 사용합니다.

`getglobalvar`, 전역 `toggle`, `#each`처럼 공식 플러그인 API만으로 정확히 재현할 수 없는 문법이나 손상된 조건 블록은 추측해서 실행하지 않습니다. 컨텍스트 화면의 관련 자료 제목 옆에는 **미지원 문법** 배지를 표시하고, 내용을 펼치면 해당 원문을 별도 색으로 강조합니다. 각 항목 가장 오른쪽의 **전달 안 함/전달함** 중 선택된 버튼에는 파란 테두리가 표시됩니다. 기본값인 **전달 안 함**에서는 미지원 구문이 작가에게 보내는 텍스트와 토큰 추정치에서 제외되고, **전달함**에서는 해당 항목의 미지원 원문을 그대로 전달합니다. 캐릭터 디스크립션 위의 같은 이름을 가진 두 버튼은 현재 일반 컨텍스트와 개별 로어북을 일괄 설정하며 선택 테두리는 표시하지 않습니다. 이 해석기는 `setvar`, `addvar` 등 상태를 변경하는 명령을 실행하지 않습니다.

## 본편 보호 원칙

플러그인은 캐릭터, 채팅 기록, RisuAI 데이터베이스, 테마 또는 실제 로어북 설정을 수정하는 API를 호출하지 않습니다.

활성 메모가 있을 때만 본편 모델 요청 직전에 메시지 배열을 복제한 뒤, 복제본의 마지막 사용자 메시지 끝에 아래 형식으로 덧붙입니다.

```text
(Memo(1): 메모 내용)
```

저장된 사용자 메시지 자체는 바뀌지 않습니다. 메모 주입에 실패하면 원래 요청을 그대로 반환하도록 설계되어 있습니다.

메모로 직접 활성화된 로어북은 RisuAI의 실제 로어북 상태를 변경하지 않고 요청 사본에 별도의 시스템 참고자료로 추가됩니다. 메모 또는 해당 폴더를 끄면 이후 요청부터 보충 활성화도 중단됩니다.

mainDom 권한이 허용된 상태에서는 메모가 실제로 주입된 요청의 마지막 사용자 메시지 아래에 **작가 메모 · 이번 모델 요청에만 포함됨** 표식과 전송 내용을 표시합니다. 답변이 도착해 화면이 다시 그려져도 다음 사용자 요청을 보내기 전까지 유지됩니다. 이 표식 역시 화면에만 덧붙이는 표시이며 채팅 기록에는 저장되지 않습니다.

## 로어북 ON / OFF / AUTO

- **ON**: 해당 항목을 작가에게 항상 제공합니다.
- **OFF**: 해당 항목을 작가에게 제공하지 않습니다.
- **AUTO**: 현재 본편의 검색 깊이·전체 단어 설정·재귀 검색 설정과 로어북 키를 이용해 플러그인이 읽기 전용으로 활성 여부를 판정합니다.

AUTO에서는 일반 키, 정규식 키, 보조 키, 추가 키, 제외 키, 항목별 검색 깊이, 전체 단어 일치, 항상 활성화 및 안전하게 읽을 수 있는 활성화 데코레이터를 처리합니다. 판정 이유는 다음처럼 통합하여 표시합니다.

- `AUTO · 항상 활성화`
- `AUTO · 본편 대화에서 활성화 키 발견`
- `AUTO · 활성 메모에서 활성화 키 발견`
- `AUTO · 로어북 재귀 검색에서 활성화 키 발견`
- `AUTO · 검색 깊이 내 활성화 키 없음`
- `AUTO · 미지원 기능이 있어 작가에게 미포함`

본편의 `recursiveScanning`이 ON일 때만 활성 로어북 내용으로 다른 로어북을 재귀 검색합니다. 개별 항목의 `recursive`, `unrecursive`, `no_recursive_search` 설정은 RisuAI와 같은 우선순위로 적용합니다. 본편 재귀 설정의 현재 ON/OFF 상태는 컨텍스트 상단에서 확인할 수 있습니다.

RisuAI의 `folder` 항목은 로어북 본문이 아닌 폴더 메타데이터로 처리합니다. 폴더 자체는 작가 컨텍스트와 로어북 개수에서 제외되고, 실제 항목은 소속 폴더 아래에 묶여 표시됩니다. 폴더 단위 ON/AUTO/OFF는 소속 항목 전체에 적용되며 본편 로어북 설정을 변경하지 않습니다. `child` 항목은 폴더 하위 항목이 아니라 현재 채팅에서 로컬 활성화한 캐릭터 로어북 참조로 해석하여 원본과 합치고, 같은 본문이 중복 전달되지 않게 합니다.

활성 확률은 플러그인에서 추첨하지 않습니다. 100% 미만의 확률 설정이 있는 AUTO 항목은 `미지원 기능이 있어 작가에게 미포함`으로 표시하며, 세부 배지에서 `활성 확률 설정 미지원`을 확인할 수 있습니다. 사용자가 ON으로 지정하면 확률과 관계없이 원문을 작가에게 포함합니다.

CBS를 해석할 수 없는 경우의 `미지원 문법`과 활성 여부를 결정할 수 없는 `미지원 기능`은 별도로 표시합니다. 미지원 CBS가 있는 로어북도 활성 여부 자체를 판정할 수 있으면 포함될 수 있으며, 미지원 원문의 전달 여부는 해당 로어북 오른쪽 선택 버튼을 따릅니다.

AUTO 판정은 RisuAI 본편과 같은 자료와 설정을 가능한 범위에서 따르지만, 공식 플러그인 API로 공개되지 않은 전역 상태나 본편 내부의 이미 완료된 무작위 결과까지 복제하지는 않습니다. 어떤 선택도 본편 로어북 상태를 변경하지 않습니다.

캐릭터별 `scanDepth`가 지정되어 있으면 그 값을 사용합니다. 지정되어 있지 않을 때 RisuAI의 사용자 전역 `loreBookDepth`는 플러그인 API에 공개되지 않으므로 RisuAI 기본값과 같은 5를 사용합니다. 전역 검색 깊이를 별도로 바꿔 사용하는 경우에는 작가용 AUTO 판정과 차이가 날 수 있습니다.

설정 화면에는 별도의 로어북 기본 상태가 없습니다. 새 항목의 기준은 AUTO이며, 컨텍스트 화면의 **전체 ON / 전체 AUTO / 전체 OFF** 버튼으로 현재 봇의 작가용 로어북을 한 번에 변경할 수 있습니다. 이후에도 각 항목의 상태를 개별적으로 다시 조정할 수 있습니다.

## 권한

- 페르소나 설명을 읽기 위한 제한적 데이터베이스 읽기 권한
- 활성 메모를 본편 모델 요청의 사본에 추가하기 위한 replacer 권한
- 플러그인 iframe을 비차단 플로팅 패널로 조절하고, 실제 메모 주입 내용을 채팅 화면에 시각적으로 표시하기 위한 mainDom 권한

권한이 거부되면 해당 기능만 사용하지 않으며, 본편 데이터에는 변경을 가하지 않습니다.

플러그인은 가져와 초기화될 때 필요한 권한 확인을 즉시 요청합니다. 다만 RisuAI가 같은 내부 이름의 이전 플러그인 권한·실행 상태를 캐시한 경우에는 업데이트 직후 한 차례 새로고침해야 새 권한 안내가 나타날 수 있습니다.

## 개발 확인

개발 원본은 기능별로 나뉜 `src` 폴더의 TypeScript 파일입니다. 파일 이름 앞의 번호가 빌드 및 실행 순서를 나타냅니다.

처음 한 번 개발 도구를 설치합니다.

```bash
npm install
```

코드를 수정한 뒤 정적 검사를 실행합니다.

```bash
npm run check
```

배포 파일을 만들 때는 다음 명령을 실행합니다.

```bash
npm run build
```

빌드 결과는 루트의 `summon_author_v1.1.0.js`에 생성됩니다. 이 파일만 RisuAI에 설치하면 되며 외부 라이브러리나 네트워크 의존성이 없습니다. 배포용 JS를 직접 수정하지 말고 `src`의 개발 원본을 수정한 뒤 다시 빌드합니다.
